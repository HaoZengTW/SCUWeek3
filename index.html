01A / WHY SO MANY MODELS

為什麼不選最強的就好？

能力
同一題，難度不同

分類與抽取通常不需要最高階推理；跨文件判斷、策略分析才需要更強能力。

速度
有些工作不能等

即時客服、語音互動與大量批次任務，速度可能比「多想 20 秒」更重要。

成本
每次呼叫都在花錢

同樣一萬次任務，單次差一點點錢，放大後就可能形成顯著的月成本差異。

任務真的需要最強模型嗎？模型選型的目標不是找出「最強」，而是找出「足以完成工作、成本合理、速度可接受」的模型。
01B / MORE THAN INTELLIGENCE

模型差異，不只有聰不聰明

實際工作還會受到資料型態、工具能力與部署方式影響，因此同一個能力級距也可能有不同模型。

輸入資料
文字不是唯一輸入

圖片、文件、聲音、影片需要不同多模態能力；不是每個模型都支援相同輸入。

工具能力
回答 vs. 做事

有些場景只要文字生成，有些需要搜尋、函式呼叫、程式執行或 Agent 能力。

部署與治理
雲端、地端、混合

資料敏感度、法規與網路環境，也會限制模型可以在哪裡執行。

選一個工作看看
大量、規則明確優先看速度與成本，不一定需要最大模型。先用最小可行模型驗證準確率，再升級。
02 / EMPLOYEE ANALOGY

模型不是越大越好

Luna｜行政助理
快、便宜、適合規則明確

  • 格式整理
  • 大量摘要
  • 高流量重複任務
API 級距：低成本
Sol｜資深專員
需要判斷力的日常工作
  • 文件比較
  • 報告撰寫
  • 一般分析
  • 中度複雜推理
API 級距：中成本
Astra｜專家顧問
高難度、多限制、答錯代價高
  • 複雜推理
  • 深度研究
  • 大型文件工作
  • 困難 Agent 任務
API 級距：高成本
管理原則：讓最便宜、最快，且「足以完成工作」的模型先做。只有當品質不足時，再往更高能力級距升級，而不是所有任務一律使用最強模型。

03B / TASK COMPLEXITY

任務複雜度

這是本課程使用的教學量尺，不是產業通用標準。判斷四件事：步驟數、規則是否明確、需要整合多少資訊、是否存在衝突或取捨。

LEVEL 1

直接執行

單一步驟、規則明確、幾乎不需判斷。

例：把留言分成詢價／客訴。
LEVEL 2

整理轉換

2–3 個明確步驟，輸出格式固定。

例：Email 擷取公司、姓名、日期。
LEVEL 3

比較判斷

整合多項資訊，依清楚條件做選擇。

例：依 5 個條件比較供應商。
LEVEL 4

多步推理

條件互相影響，存在例外、衝突與取捨。

例：插急單後判斷延誤與替代方案。
LEVEL 5

開放策略

目標不完全明確，資訊不完整，需要權衡風險。

例：規劃企業 AI 導入路線與優先順序。
模型建議Level 2 通常先從 Luna 測試。
LEVEL 2｜整理轉換

從 Email 擷取公司、聯絡人、需求與日期

規則清楚、欄位固定，需要少量理解，但不需要複雜取捨。

03C / REASONING EFFORT

同一個模型，也可以決定「要想多久」

Model 決定請誰做；Reasoning Effort 決定要他投入多少推理資源。推理越深不代表每一題都更好，通常也會增加等待時間與 Token。

LOW

快速判斷

分類、擷取、改寫、規則明確。

MEDIUM

一般分析

比較資料、一般商務判斷。

HIGH

仔細推理

多條件決策、除錯、規劃。

XHIGH / MAX

高難度問題

只有實測證明值得時才提高。

用同一個 Sol 做同一題
MEDIUM一般分析：合理起點先取得足夠的判斷品質，再用實際結果決定是否需要提高或降低推理深度。

07 / RECALL

挑選大型語言模型要注意什麼？

① 任務分類、摘要、比較、策略？
② 複雜度Level 1–5？
③ Reasoning需要想多深？
④ 品質風險答錯的代價？
⑤ 速度1 秒、5 秒、1 分鐘？
⑥ 成本一次多少？一天幾次？
⑦ 資料型態文字、圖片、文件、語音？
⑧ Tool / 部署要即時資料？資料能出去嗎？
還少一個問題：同一個模型，要在哪個平台跑？Provider / Inference Platform 也會改變速度、價格、可用模型與工具能力。

11 / RELIABILITY

模型越強，還是可能會答錯！！

可靠性不是只靠升級模型。先分辨錯誤發生在哪一層，再決定要換模型、換資料、加 Tool，還是加人工覆核。

不知道
幻覺

沒有資料卻產生看似合理答案。

資料
Garbage in

輸入資料錯，模型再強也可能得到錯結論。

推理
漏條件

複雜限制下漏掉例外或互相衝突的條件。

Tool
外部失敗

API 過期、查詢失敗、資料庫回傳不完整。

可靠系統 = 模型 + 正確資料 + Tool + 驗證規則 + 適當人工覆核答錯代價越高，越不能只靠「換成最強模型」。
